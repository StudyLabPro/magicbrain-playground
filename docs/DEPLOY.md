# Раннбук развёртывания

## Что здесь необратимо

Почти всё обратимо: контейнеры удаляются, образ удаляется, каталог `var/`
копируется или стирается, соседние сервисы стек не трогает. Необратим **один
шаг — первое включение внешнего маршрута** (шаг 7):

- Traefik заказывает у Let's Encrypt сертификат на `MBP_DOMAIN`, и имя домена
  навсегда попадает в публичные логи Certificate Transparency;
- сканеры приходят по этому имени в течение секунд — в нашем случае это был
  51 запрос с 17 адресов за первые 45 минут (`/`, `/wp-json/`, `/xmlrpc.php`,
  `/.env`). Под basic-auth все получили `401`, содержимое не утекло, но имя
  домена раскрыто навсегда.

Отсюда правило: имя выбирается **до** первого включения маршрута, а до тех пор
всё проверяется локально — см. «Проверка без выпуска сертификата».

## Предусловия

- Свободны порты `127.0.0.1:8007` и `127.0.0.1:8008`. **Проверить прямо перед
  запуском:** `ss -ltn | grep -E ':(8007|8008)'`. Если заняты, поменять
  `MBP_PORT` / `MBP_API_PORT` в `.env`.
- Для сборки нужен локальный клон MagicBrain (`MB_SRC`, по умолчанию
  `../MagicBrain`), иначе `make prepare` откажется. Для запуска уже собранного
  образа он не нужен.
- Внешняя сеть обратного прокси (`MBP_EDGE_NETWORK`) нужна **только** для
  шага 7. Шаги 1–6 её не касаются: стек поднимается в собственной сети.
- Домен из `MBP_DOMAIN` должен резолвиться на этот хост до включения маршрута,
  иначе ACME не пройдёт http-01.

## Шаги

Каждый шаг — с проверяемым критерием. Если критерий не выполнен, следующий шаг
не начинается.

**1. Корпуса.** Нужны только для пересборки; тексты уже лежат в репозитории.

```bash
make corpora            # нужна сеть; можно пропустить
```
*Критерий:* `data/corpora/manifest.json` существует и `make test` проходит
(тест сверяет sha256 каждого корпуса с фактическим файлом).

**2. Снимок исходников MagicBrain и `.env`.**

```bash
make prepare
```
*Критерий:* в выводе — SHA MagicBrain, состояние его дерева и `build_id`.
Дерево `dirty` означает, что в подмодуле чужие незакоммиченные правки: в образ
они не попадут (берётся `git archive HEAD`), но это повод спросить, чьи они.

**3. Сборка образа.**

```bash
make build
```
*Критерий:* последняя строка — `образ magicbrain-playground:<build_id> собран`,
и `docker images magicbrain-playground` показывает этот тег. Тег совпадает с
`MBP_BUILD_ID` в `.env.build` и не меняется при последующих запусках.

**4. Запуск.**

```bash
make up
```
Каталоги состояния создаются и отдаются пользователю контейнера самим
`make up`; отдельный `chown` больше не нужен. Маршрут наружу выключен, контейнер
к общей сети хоста не подключён.

*Критерий:* строка `плейграунд: http://127.0.0.1:8007/ (маршрут наружу:
выключен)`.

**5. Проверка.**

```bash
make status
```
*Критерий:* два контейнера `healthy`;
`{"status":"healthy","service":"magicbrain-playground"}` на `:8007` и
`{"status":"healthy","service":"magicbrain-research"}` на `:8008`.

Изоляция проверяется отдельно:

```bash
docker network inspect mbplay-private --format '{{range .Containers}}{{.Name}} {{end}}'
docker network inspect "$MBP_EDGE_NETWORK" --format '{{range .Containers}}{{.Name}} {{end}}'
```
*Критерий:* в первой сети — `mb-playground` и `mb-api`; во второй их нет.

**6. Прогон сценариев (не обязателен для развёртывания).**

```bash
make smoke              # ~10 минут на 100000 шагов; пишет var/scenarios-summary.json
make runs-doc           # пересобирает docs/RUNS.md из файлов прогонов
```
*Критерий:* `make smoke` завершается строкой `сводка: var/scenarios-summary.json`
и не падает на сплошной сверке перечитанных прогонов.

**7. Маршрут наружу — отдельное решение.** См. «Что здесь необратимо».

Под паролем (по умолчанию):

```bash
sed -i 's/^MBP_TRAEFIK_ENABLE=.*/MBP_TRAEFIK_ENABLE=true/' .env
export MBP_AUTH_MIDDLEWARE=<имя middleware с basic-auth>
make up                              # подключит docker-compose.publish.yml
curl -sI "https://$MBP_DOMAIN/"      # ОБЯЗАТЕЛЬНО: ожидается 401
```
*Критерий:* контейнер появился в сети прокси, и запрос **без пароля возвращает
`401`**. Если вернулось `200` — немедленно `MBP_TRAEFIK_ENABLE=false` и
`make up`: basic-auth не применился. Первый запрос может ответить `404`, пока
идёт выпуск сертификата — повторить через полминуты.

Открытый показ без пароля — другой оверлей и другое решение:

```bash
sed -i 's/^MBP_DISCLOSURE=.*/MBP_DISCLOSURE=public/' .env
MBP_ROUTE_MODE=open make up          # подключит docker-compose.public.yml
curl -s "https://$MBP_DOMAIN/api/meta" | head -c 200
```
*Критерий:* `public_mode` в ответе `true`, `DELETE /api/runs/<id>` отвечает
`403`, а `GET /api/corpora` не содержит путей файлов на хосте.

**8. Уборка после проверки.**

```bash
make clean-images       # удалит теги magicbrain-playground, кроме текущего
docker system df        # висячие слои и кеш сборки — отдельное решение
```
*Критерий:* `docker images magicbrain-playground` показывает один тег.
`docker image prune -f` и `docker builder prune` затрагивают весь хост, поэтому
их принимает тот, кто за хост отвечает, а не этот раннбук.

## Проверка без выпуска сертификата

Пока решение о публикации не принято, маршрут проверяется локально — Traefik
при этом не участвует и сертификат не заказывается:

```bash
curl -s -H "Host: $MBP_DOMAIN" http://127.0.0.1:8007/health
```

Это проверяет сам сервис. Basic-auth живёт в middleware обратного прокси, и
проверять его на живом маршруте (то есть с выпуском сертификата) не нужно.

## Проверка режима раскрытия

`MBP_DISCLOSURE=public` — режим открытого показа: сценарии и прогоны те же, но
стенд только показывает, а не редактирует. Проверяется вторым экземпляром, не
трогая рабочий:

```bash
MBP_NAME=mbpub COMPOSE_PROJECT_NAME=mbplay-public \
MBP_PORT=8009 MBP_API_PORT=8010 MBP_DISCLOSURE=public \
docker compose --env-file .env --env-file .env.build -f docker-compose.yml up -d
```

| проверка | ожидание |
|---|---|
| `GET /api/meta` → `enabled_experiments` | все четыре сценария, включая нейрогенез |
| `GET /api/runs/<id нейрогенеза>` | прогон отдаётся целиком |
| `GET /api/corpora` | без путей файлов на хосте |
| `DELETE /api/runs/<id>` | `403` |
| `MBP_DISCLOSURE=puplic` (опечатка) | контейнер не стартует |

Режим `internal` — для своих: удаление прогонов разрешено и пути видны.

## Откат

```bash
make down                                  # контейнеры и своя сеть; тома не трогаются
docker image rm magicbrain-playground:$(sed -n 's/^MBP_BUILD_ID=//p' .env.build)
```

Данные прогонов остаются в `var/` — обычный каталог на диске. Если маршрут был
включён, откат снимает его (`MBP_TRAEFIK_ENABLE=false` + `make up`), но имя
домена из CT-логов не убирает: это уже не откатывается.

## Эксплуатационные границы

- Суммарный лимит: 4 vCPU и 6 GB (`deploy.resources.limits`), плюс 256
  процессов на контейнер. Замеренное потребление сильно ниже: во время прогона
  `docker stats` показывает ~103% CPU (одно ядро) и 78 MB у плейграунда, 0.1%
  и 47 MB у `mb-api`. Образ — 262 MB, один на оба контейнера.
- Файловая система контейнеров смонтирована только на чтение; писать можно в
  `/data` (это `./var`) и в `tmpfs /tmp` на 64 MB.
- Прогонов на диске — не больше `MBP_MAX_RUNS` (500); при сохранении нового
  самые старые удаляются вместе с моделями.
- Одновременных прогонов — `MBP_MAX_WORKERS` (по умолчанию 2). Больше нет
  смысла: numpy-ядро однопоточное (`*_NUM_THREADS=1` выставлены намеренно,
  чтобы прогон не расползался по всем ядрам хоста).
- Логи ограничены `json-file` 10 MB × 3 на контейнер.

## Соответствие чисел и сборки

Числа в `docs/RUNS.md` привязаны к конкретной сборке: каждый прогон несёт свои
`build_id`, SHA MagicBrain и SHA плейграунда, а шапка документа собирается из
самих прогонов. Развёртывание из более позднего коммита даёт другой тег — это
ожидаемо и не делает документ неверным; чтобы числа снова относились к текущей
сборке, нужен повторный `make smoke && make runs-doc`.
